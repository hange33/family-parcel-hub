# P0 · 原版 parcly 验证清单

> 目的：确认原项目「账号抓取」在三家平台上**还能不能用**。
> 不通过就不改代码，直接换方案，避免白投入。

## 一、装包

| 机型 | 装哪个 |
|---|---|
| 2017 年后的手机（绝大多数） | `parcly-1.0.0-arm64-v8a.apk`（24.3 MB） |
| 老 32 位机 / 不确定 | `parcly-1.0.0-universal.apk`（57.1 MB） |

下载页：https://github.com/Granter-z/parcly/releases/tag/v1.0.0

- 安装时需允许「未知来源应用」
- 要求 Android 7.0 以上
- GitHub 直连慢可挂代理，或先用 `universal` 包一次装成

## 二、两台手机分开装（关键）

- **你装你的，对象装对象的**，各自登录各自账号
- ⛔ 千万不要在一台手机上登录两个拼多多账号 —— 服务端单设备会话，必互踢
- 建议顺序：**淘宝 → 京东 → 拼多多**（拼多多放最后，最容易出状况）

## 三、三个平台分别验什么

| 平台 | 要看的东西 | 通过标准 |
|---|---|---|
| 淘宝/天猫 | 首页卡片上的取件码 | 形如 `8-3-2015` 的货架码（菜鸟驿站），不是「后 5 位 98898」 |
| 京东 | 待取件卡片 + 自提码 | 有自提柜/便民柜码，外卖闪送类订单被正确排除 |
| 拼多多 | 多多驿站/代收点取件码 | 有真实码；且官方 App 是否被踢下线（记录） |

**另外记录**：
- 设置页三个平台是否都显示「已登录」
- 同步耗时（设置 → 后台同步测试 / 下拉刷新计时）
- 是否有红色报错提示（登录态失效、同步异常）

## 四、测试时机

**必须在有在途或待取件的时候测。** 没有真实包裹时，列表里只有历史订单，看不到取件码，会误判成「抓不到」。

## 五、判据

| 结果 | 结论 |
|---|---|
| 三家都能拿到码 | ✅ 全案通过 → 进 P1（NAS 服务） |
| 1–2 家能用 | ⚠️ 降级方案：能用的走自动，缺的那家走「QQ 群手动丢码」 |
| 全部失败（登录不上 / 接口报错 / 有单无码） | ❌ 停止，改走短信/通知采集方案 |

## 六、反馈给我什么

1. 三张首页截图（可打码地址）
2. 设置页「平台绑定」状态截图
3. 每家的同步耗时
4. 拼多多：官方 App 有没有被踢？重登后 parcly 里还活着吗？
5. 有没有报错文案（原样抄给我）

## 七、注意

- 测试用的就是真实账号，会有异地/新设备登录提醒，正常现象
- 拼多多若把官方 App 踢了：先在官方 App 重登，再看 parcly 是否失效——**这个结果直接决定拼多多能不能进方案**
- 别把带真实地址、手机号、订单号的截图发到公开地方
